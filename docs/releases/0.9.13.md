# WhyNavo 0.9.13

## 中文

### 图标清晰度

- 移除 Chrome favicon 重采样接口。该接口会把 21、48 或 64 像素的小图放大后伪装成 128 像素，是低清图标仍能通过检查的根因。
- 自动图标位图现在必须至少达到 192 × 192，并同时满足实际显示尺寸与屏幕像素密度要求；SVG 等矢量图继续保持无损显示。
- 清理 0.9.12 及更早版本保存的图标解析缓存，升级后会重新按新规则选择图标。
- 导入快捷导航时不再把第三方 favicon 转换地址写入用户数据；已经保存的此类地址会自动失效并重新安全解析。
- 纳米漫剧使用网站公开的官方 SVG。虎牙使用官方 512 × 512 应用图标。
- 网站没有真实高清图标时，稳定显示清晰的文字图标，不再展示模糊位图。
- 移除图标动态重采样权限，避免滚动时重新生成和替换图标。

本次更新不改变快捷导航、笔记、任务、设置或同步数据。

## English

### Icon clarity

- Removed Chrome's favicon resampling endpoint. It could upscale 21, 48, or 64 pixel artwork and report it as a 128 pixel image, allowing visibly blurred icons through validation.
- Automatic raster icons must now be at least 192 × 192 and satisfy the actual rendered size and display pixel density. Vector artwork remains resolution independent.
- Invalidated icon resolution caches created by 0.9.12 and earlier so every shortcut is resolved under the stricter policy.
- Imports no longer persist third-party favicon transformation URLs. Previously stored provider URLs are ignored and safely resolved again.
- Namistory now uses its published official SVG. Huya uses its official 512 × 512 app artwork.
- When a site has no genuinely sharp icon, WhyNavo uses a stable text icon instead of displaying a blurred bitmap.
- Removed the dynamic favicon resampling permission so scrolling cannot regenerate or replace shortcut artwork.

This update does not modify shortcut, note, task, setting, or sync data.
