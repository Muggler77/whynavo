# WhyNavo 0.6.0

## 中文

0.6.0 是面向公开注册上线的安全与发布基础版本，数据结构仍为版本 1。

- 注册、登录、密码重置、普通密码修改和删除账号增加 Cloudflare Turnstile 一次性验证，降低批量注册、撞库和滥用风险。
- 注册页要求用户明确同意隐私说明与服务条款，并把所接受的文档版本记录到账号元数据；公开隐私说明与服务条款均提供完整中英文内容。
- 隐私说明明确披露 Supabase Auth 在浏览器中维持访问与刷新会话令牌；这些令牌不会进入持久化应用数据、导出备份或同步快照。
- 验证码加载增加 15 秒超时和可见的重新加载操作，网络或内容拦截器导致验证失败时不再无限等待。
- 账号永久删除改为由云端再次验证当前密码、一次性验证码、账号身份和调用来源；仅窃取登录令牌不能跳过二次验证直接删除账号。
- 删除账号函数同时拒绝缺少浏览器来源标头的请求，不为脱离官方网页或扩展的直接调用保留匿名来源例外。
- 验证页使用独立的 Pages 静态页面，浏览器扩展通过受限 `postMessage` 获取令牌；令牌不会写入 IndexedDB、云端快照或仓库。
- 官方生产构建在缺少 Supabase、Turnstile 或 Pages 配置时直接失败，避免部署出一个看似可用但无法注册的版本。
- 未打包扩展检测到新版本后会直接打开最新 GitHub Release，不再让普通用户从仓库源码中寻找安装包。
- 网页更新期间会同时保留当前与上一版应用外壳，已打开页面所需的分包文件不会因新版本切换而被提前清除；网页端可直接刷新更新，未打包扩展会显示可信发布包入口。
- 升级时会保留旧快捷方式和文件夹记录，但自动移除旧版本遗留的明文 HTTP 图标、壁纸和相框图片地址，避免继续向不安全端点发送图片请求。
- 远程版本清单的版本号、数据版本和严重级别使用封闭校验，发布链接只接受官方 GitHub Releases，篡改的清单不能把用户导向任意站点。
- 修复 Service Worker 把隐私页或认证验证页错误缓存为主页的问题，验证页不再被离线缓存替代。
- 密码重置链接现在会自动打开账号面板并展示新密码输入；注册验证和密码重置邮件均使用带 WhyNavo Logo、来源说明和中英双语安全提示的正式模板。
- 找回密码权限只接受 Supabase 已验证的恢复事件，网址参数本身不能绕过当前密码验证。
- 普通密码修改会用新的 Turnstile 令牌重新验证当前邮箱和密码，并核对返回的账号 ID 后才提交新密码。
- 修改密码使用的隔离临时会话会在成功或失败后立即撤销，不会在服务端留下无主设备会话。
- 新注册和密码更新要求至少 12 个字符；正式环境同时要求 Supabase 在服务端执行相同下限，避免绕过前端直接创建弱密码。
- 注册、登录和设置新密码会通过 Have I Been Pwned 的隐私保护范围接口检查已知泄露密码；仅有 5 位 SHA-1 前缀离开设备，填充结果在本机完成比对。注册和设置新密码在检查失败时停止；已验证成功的登录会在泄露或检查服务不可用时显示安全提醒，但不会因第三方服务故障锁住现有账号。
- 云端快照读取改用账号绑定接口，不再允许客户端直接读取表；读写都会在数据库中验证 Supabase 会话，并执行 90 天总期限和 30 天闲置期限。
- 已发布的 0.5.x 客户端在过渡期仍可通过 RLS 读取自己的快照；兼容写入入口继续执行账号归属、会话期限、速率和并发版本检查，直到 0.6.0 安装包公开且更新清单激活后才撤销。
- 本机、导入、恢复与云端数据在显示前执行完整结构校验；账号加载失败时恢复原本机状态，不再用空白数据覆盖未登录内容。
- 新用户点击邮箱验证链接自动登录时，也会先把未登录期间创建的主页数据安全合并到账号，并显示明确的验证成功提示；离线启动继续使用已缓存账号分区。
- 匿名数据并入已有账号时改为保留双方记录、优先账号设置并保留当前设备的照片与自定义壁纸，避免空云端或默认设置覆盖已有内容。
- 修改时间改为单调逻辑时钟；客户端见过较新的本机或云端时间后，后续编辑不会因系统时钟回拨或设备时钟偏差被错误判为旧数据。
- 增加公开仓库的 CI、依赖更新检查、安全漏洞报告指引和生产配置结构检查。
- 增加固定到 GitHub 官方提交的 CodeQL 语义安全分析，每次主分支提交、拉取请求和每周计划任务都会扫描 JavaScript 与 TypeScript。
- CI、Pages 部署和正式 Release 会独立编译检查三个 Supabase Edge Function，避免前端构建通过但邮件、汇率或账号删除函数存在语法错误。
- Chrome Web Store 显示名改为 `WhyNavo - Local-first New Tab`，在保留产品名的同时与商店内其他同名扩展区分；短名称仍为 `WhyNavo`。
- 正式巡检和加密数据库备份增加 `WHYNAVO_PRODUCTION_ENABLED` 上线开关，避免邮件、备份和法律配置尚未完成时由定时任务制造错误的生产事故告警；手动预检不受影响。
- 正式发布会先创建仅维护者可见的草稿 Release；兼容云端与 Pages 预发布检查通过后才公开安装包，再激活更新清单并撤销旧接口，避免任何失败节点让旧用户失去可用同步或下载入口。发布和部署也受上线开关保护，不能在准备未完成时误触发。
- 图标解析会短期记住整条候选链的失败结果，六小时后自动重试；离线、被拦截或没有图标的网站不再在每次打开时重复发起全部请求，移动端占用与闪烁进一步降低。
- 每次扩展构建都会检查最终目录并拒绝网页托管专用或浏览器保留文件，防止 `_headers`、`_redirects`、`CNAME` 或 `*` 开头文件再次导致 Chrome 无法加载扩展。
- 账号删除后的本机清理重试按账号 UUID 隔离；不会因某个账号的删除状态不明而清除其他未申请删除的账号分区。服务端明确判定对应会话失效后，只清理已明确申请删除的账号；如果登录凭据已被用户另外清除，则清理所有仍标记为待删除的账号分区。如果同一账号后来仍能通过在线验证，则解除该账号的本机防复活标记并安全恢复。
- 浏览器书签 HTML 改由不会创建 DOM、执行脚本或加载外部资源的有界解析器读取；脚本协议、超大文件、恶意标签和异常属性不能进入网站数据。
- 网站与文件夹图标在进入图片元素前再次执行 HTTPS、协议、凭据和长度校验；Google、DuckDuckGo 与 Simple Icons 等提供方通过解析后的精确主机和路径识别，不能被相似恶意域名冒充。
- 线上安全检查会解析 CSP 指令和精确来源列表，不再以可能被前后拼接绕过的字符串包含关系判断 Turnstile 来源。
- 加密备份检查改为在打开文件后通过同一个文件描述符读取属性与内容；Supabase 管理脚本只允许经过审查的端点、方法和有界请求体。
- 增加发布前仓库隐私与密钥扫描，自动阻止个人导出、私密环境文件、服务端密钥、本机路径、旧域名和旧品牌词进入公开版本。
- CI 和 Release 还会扫描全部可达 Git 历史及提交作者邮箱，避免已经删除的个人路径、旧域名或密钥继续留在公开提交中。
- 损坏的账号本机缓存会先按账号隔离保存，但不再被当作有效本机快照参与云端合并，避免默认设置污染已有云端数据。
- 浏览器禁用或损坏本机存储时会明确进入临时内存状态并暂停同步，不再永久停留在加载页。
- 认证邮件投递增加事件级幂等键、3.5 秒提供商超时和 Supabase 标准错误响应，安全邮箱变更的两封邮件并行发送；云端重试不会重复发送同一事件，公开汇率代理增加来源大小、超时、方法和陈旧缓存回退边界。
- 认证邮件 Hook 对签名通过后的事件结构和收件地址继续做封闭校验，所有响应禁止缓存；损坏或未来不兼容的事件会安全失败，不会生成错误验证邮件。
- 认证邮件不再直接暴露可被邮箱安全扫描提前使用的一次性验证地址；令牌只放在不会发送给 Pages 服务器的 URL 片段中，用户在 WhyNavo 安全确认页真实点击后才前往 Supabase 验证。
- 大型网站集合改为接近视口时分批挂载图标组件，首屏不再一次创建数千个图片节点；慢网络下的清晰图标候选也获得更合理的加载时间。
- 关闭自动网站图标查询时不再预先解析或连接第三方图标服务；已解析图标继续使用账号分区的本机有界缓存。
- 备份、本机缓存和云端快照改为封闭数据模型校验；未知嵌套字段、非 HTTP(S) 网站地址和非图片图标协议会在合并或显示前拒绝。
- 从备份读取的动态壁纸和照片地址在进入 CSS 前统一转义，引号、反斜杠和换行不能跳出背景图片值。
- 书签和网站导入会拒绝内嵌凭据、活动 SVG、脚本协议和无效相对地址，单条坏记录不会中断整次导入。
- 从早期全局存储版本升级时，旧数据会先留在未绑定账号的隔离区，不会自动归属任何登录账号；用户登录确认原账号后，可在账号面板显式导入，成功写入当前账号分区后才移除旧键。
- 天气和经纬度缓存改为账号分区；退出、删除或切换账号会立即移除上一账号的可见位置天气。
- 天气来源链接不再把坐标拼入第三方搜索请求；城市、坐标和天气结果只在当前账号的本机分区缓存，不进入云端同步或完整备份。
- 旧版本已缓存的天气卡片在升级后会立即改用 Open-Meteo 官方来源，不需要等待下一次天气刷新才能移除旧的坐标搜索链接。
- 首次登录合并未登录数据时，会在同一个本机存储事务中写入账号分区并清空已消费的匿名分区，避免异常退出后把同一批数据再次带入其他账号。
- 该原子采用事务现在会在任何云端读取或上传之前完成；如果本机存储失败，登录激活会回滚且不会把尚未消费的匿名数据同步到目标账号。
- 登录加载期间继续产生的未登录修改，会在账号正式显示前再次原子写入账号并清空匿名分区，不能在未来登录另一个账号时被重复带入。
- 账号切换前如果旧账号数据因本机存储故障无法落盘，页面会保留可导出的内存副本、暂停同步并记录待切换账号；存储恢复后才继续激活，不能停留在云端会话与可见数据不一致的无重试状态。
- 新安装默认不申请或读取设备位置；扩展清单仅把定位列为可选权限，只有用户在设置中主动开启“使用当前位置”后才请求并调用浏览器定位。
- 汇率云函数兼容 Supabase 当前的 publishable/secret 可轮换密钥，不再把 publishable key 当作旧式 Bearer JWT；未登录用户也能正常读取公开汇率缓存。
- 汇率缓存表启用行级保护并撤销普通客户端权限，只有服务器函数可以更新或读取原始缓存表。
- 同步写入 RPC 显式撤销匿名执行权限，只允许已认证用户调用；函数内部的账号检查和表级最小权限继续作为额外边界。
- 同步写入 RPC 的运行时搜索路径锁定为空，避免安全定义函数受同名数据库对象影响。
- 数据库自动启用 RLS 的事件触发函数不再能由公开 API 角色执行；它仍只在数据库建表事件中按设计运行。
- 本机、备份和云端时区会在渲染前验证；损坏或伪造的时区值会被拒绝并回退到安全默认值，不再导致整页无法打开。
- 天气、定位和汇率响应增加超时、大小与字段校验；损坏缓存不会进入小组件渲染。
- 完整备份恢复增加适合移动设备的文件大小边界，设置页明确提醒备份可能包含私人照片、便签和待办。
- 多设备并发删除文件夹或分类时，仍在另一设备编辑的网站会回到可见的根级入口；删除分类也会同步移除关联的自定义导航入口，避免数据仍存在却无法找到。
- 旧版默认入口清理不再按网址和标题猜测数据来源，用户自己添加的 Google、YouTube 等网站不会在升级或同步时被误删。
- 便签连续发生多次多设备冲突时会合并保留所有替代正文；如果冲突内容过大，则创建可见的“同步冲突副本”，避免为满足字段大小限制而截断用户内容。
- 便签冲突判断以本设备最后已见的云端版本为基线；普通连续编辑不再把每个旧正文误存为冲突，只有两端都在基线后修改时才保留替代正文。
- 账号激活期间如果认证会话失效，会立即退出本机会话并切回匿名数据，不会把该账号的缓存数据继续显示为已登录状态。
- 离线启动时如果浏览器中只有登录会话、却没有该账号的真实本机数据，应用会继续显示未登录分区并等待联网恢复，不会生成空白账号快照覆盖云端；账号认证成功但数据暂时读取失败时也采用同一安全恢复流程。
- 自动同步发现服务端会话已不存在时会立即隐藏账号数据并切回未登录分区，不会只改变登录状态文字而继续暴露原账号内容。
- 每次自动或手动同步使用独立任务锁；旧账号的延迟任务结束时不能释放新账号正在使用的同步锁。
- 时区选择器默认只挂载常用时区，搜索结果也有数量上限，避免设置页一次创建数百个选项；旧版本缺少定位设置时继续按未授权处理。
- 手机端滚动现在识别真正可滚动的应用容器，不再把正常上下滑动误判为主页与网站页切换。
- 不同弹窗之间切换时会在绘制前回到内容顶部，不再继承上一个弹窗的移动端滚动位置。
- 自定义导航页面与其分类在多设备合并期间短暂不同步时，会保留当前页面筛选，不再突然跳到全部网站。
- 普通退出仍只影响当前设备；账号面板新增独立的“退出所有设备”，用于撤销该账号在其他设备上的刷新会话。
- 断网或认证服务异常时，退出操作仍会清除本设备持久会话并立即隐藏账号数据；界面会明确区分“本机已安全退出”和“其他设备会话已由服务端成功撤销”。
- 如果退出前无法把最新账号数据写入本机，退出会被取消并保留当前账号页面，避免未落盘修改因切换到匿名分区而丢失。
- 同一浏览器的多个 WhyNavo 标签页现在会在一个 IndexedDB 读写事务内合并后再保存，并在同账号页面之间广播轻量更新通知；两个标签页同时编辑不同记录不会再以最后一次整份写入覆盖另一页。
- 本设备退出登录会通知同一浏览器中所有已打开的 WhyNavo 标签；即使认证服务断网，每个标签也会先保存未落盘修改再隐藏账号数据，不再留下仍显示旧账号内容的页面。
- 登录切换、手动同步、自动同步、恢复备份和退出登录的显式写入也统一经过事务合并；永久删除账号会先写入不可复活标记并通知所有同源标签页，已经开始运行的旧标签不能把已删除账号缓存重新写回。
- 新增可审计的每日数据库异地备份流程：启用所需云端凭据后，导出文件先以 AES-256-GCM 加密、数据密钥再由离线 RSA 恢复公钥封装，Cloudflare R2 只接收密文，备份失败会自动创建告警；上线门禁要求先取得成功备份和恢复演练证据，不能只凭工作流文件宣称灾备已启用。
- 删除账号云函数兼容 Supabase 当前的可轮换客户端与服务端密钥集合，即使密钥集合中没有名为 `default` 的条目也能选择有效密钥。
- 自动同步检测到本机或远端存在新变化时会先保存账号范围内的同步前回退点；无变化的定时检查不会重复上传整份快照，也不会反复覆盖该回退点。
- “本机覆盖云端”和“云端覆盖本机”增加明确二次确认；本机覆盖前会额外保存首次读取到的云端版本，并保留本机私有媒体，误操作后可从账号范围内的回退点恢复。
- Pages 自动部署会在上传前重新执行数据迁移、仓库隐私、完整公开历史和生产依赖审计；Release 还会拒绝标签、清单、版本文件、Service Worker 与发布说明不一致的版本。
- 手动重部署 Pages 必须先确认同版本的公开 GitHub Release 已存在；正式发布流水线则只接受当前标签对应的私有草稿，不能绕过安装包与云端验证顺序。
- 正式发布顺序改为先准备兼容数据库、云函数和可验证安装包，再以旧更新清单切换 Pages 应用；对应 Release 公开后才激活新版本清单，随后撤销旧的账号未绑定接口并完成最终线上检查。
- Pages 首次切换到新网页时会继续发布上一版更新清单；云端检查通过并公开对应 GitHub Release 后，第二次原子部署才激活新版本清单，之后才执行不可逆的旧接口收口，避免中途失败时出现“提示更新但无包可下载”或旧客户端无同步入口。
- 同一条受审计的生产流水线会先应用尚未执行的 Supabase 迁移并部署三个 Edge Function，再切换 Pages 前端，避免前端先使用尚未就绪的数据库或云函数。
- 生产巡检缺少 Supabase 配置时会直接失败，并实际检查认证健康与公开汇率函数；三个 Edge Function 的 JWT 验证模式已写入版本化配置，重新部署不会依赖易遗漏的命令行参数。
- 生产巡检改为每小时运行；失败时自动创建或更新 `production-alert` Issue，恢复后自动关闭，让免费 GitHub 通知成为明确的基础告警路径。
- Supabase 客户端代码块首次加载失败后可以重新尝试；版本清单增加十秒超时和 64 KB 响应上限，网络故障或异常响应不会永久卡住账号功能或占用无界内存。
- 生产配置检查会校验 Supabase 项目地址与旧式匿名 JWT 的项目引用一致；仓库扫描也会解码并拒绝服务端角色 JWT。
- 自动图标发现会依次尝试全部高分辨率站点图标位置，低于 96 像素的位图不会被放大显示；本机、私网、单标签和特殊用途主机名也不会被发送给第三方图标服务。
- 已解析图标的本机缓存改为短延迟批量写入，避免大量图标同时完成时反复阻塞主线程；远程图片地址另设 8 KB 上限，不能借用内嵌图片的容量制造超长 URL。
- 所有环境专用配置文件默认从 Git 中排除，仅保留公开示例，降低后续维护时误提交凭据的风险。
- 完整历史密钥扫描会区分真实 Resend 令牌与普通代码标识符，避免安全门禁因 `require_...` 一类变量名误报。
- 旧版浏览器只支持 `crypto.getRandomValues` 时仍会生成符合 UUID 结构的高熵 ID，响应式布局监听同时保留旧版 Safari 的兼容路径。
- 顶层故障恢复页不再向用户显示原始异常细节；本机执行发布一致性检查时可在没有标签环境变量的情况下安全使用包版本。
- 数据库安全迁移兼容全新项目和已存在项目，目标函数尚未创建时不会使整批初始迁移失败。
- 同步读写现在额外绑定当前界面所显示的账号 ID；数据库会核对该 ID 必须等于当前认证用户，旧的未绑定账号写接口已撤销。即使另一个标签页在请求中途切换账号，本次操作也只能失败，不能把两个账号的数据混合。
- 0.6.0 部署完成后，使用旧账号未绑定写接口的版本会被服务端拒绝；0.5.7 可继续通过受会话保护的 RLS 读取自己的旧快照，但遇到由 0.6.0 写入的最低版本标记后会安全停止同步并提示升级。本机数据不会被删除。官方网页刷新即可升级，未打包扩展需要替换为 0.6.0 发布包并在扩展管理页手动重新加载。
- 同一浏览器的其他标签页发生登录账号变化时，当前页面会先保存原账号分区，再安全加载新账号分区；手动同步、自动同步和登录激活都覆盖这一竞态。
- 天气城市和“使用当前位置”偏好改为严格的设备本地设置，不进入云端快照或完整备份；云端覆盖、备份恢复和多设备合并也不会重置当前设备的天气设置。
- 云端快照写入在 2 MB 大小上限之外增加账号级服务端频率限制，已登录客户端不能无限重复写入大快照；主页布局编辑也增加了可触控、可键盘操作的小组件设置按钮。
- 继续保持本地优先、账号隔离、原子同步、完整备份和账号删除逻辑；已有用户数据无需重置。

## English

Version 0.6.0 adds the production security and release foundation for public registration while keeping data schema version 1.

- Cloudflare Turnstile protects sign-up, sign-in, password recovery, normal password changes, and account deletion against automated abuse.
- Registration requires explicit acceptance of the Privacy Notice and Terms, records the accepted document version in Auth metadata, and publishes complete Chinese and English legal text.
- The Privacy Notice explicitly discloses browser-local Supabase access and refresh session tokens and confirms that they are excluded from app state, exports, and synchronization snapshots.
- CAPTCHA loading now has a 15-second timeout and a visible reload action instead of leaving blocked or offline clients waiting indefinitely.
- Permanent account deletion now re-verifies the current password, one-time CAPTCHA, account identity, and caller origin on the server; a stolen session token alone cannot bypass this check.
- The account-deletion function also rejects requests with no browser Origin header instead of retaining a direct-call exception outside the official web app or extension.
- The verification page is hosted separately on Pages. The browser extension receives a short-lived token through origin- and frame-checked `postMessage`; the token is never stored in IndexedDB, cloud snapshots, or the repository.
- Official production builds fail when Supabase, Turnstile, or Pages configuration is missing, preventing a deployment that appears live but cannot register users.
- Unpacked extensions now send users directly to the latest GitHub Release when an update is available instead of making them search the source repository for an installable package.
- Hosted upgrades retain both the current and previous application shells so an already-open page does not lose lazy chunks during a production cutover. Hosted users can refresh in place, while unpacked extensions receive a trusted release-package action.
- Upgrades preserve legacy shortcuts and folders while removing plaintext HTTP icon, wallpaper, and photo-frame references left by older versions, preventing continued image requests to insecure endpoints.
- Remote update manifests use closed validation for versions, schema level, and severity, and release links are restricted to the official GitHub Releases path so a modified manifest cannot redirect users elsewhere.
- Fixed a Service Worker bug that could cache the privacy or verification page under the home-page cache key; the verification page is now excluded from offline navigation caching.
- Offline requests now prefer the current release cache; the retained previous cache is used only as a fallback, so an upgraded browser cannot serve an older page merely because that cache was created first.
- Official release builds now reject a Supabase URL for any project other than the reviewed WhyNavo production project, preventing a valid-looking but incompatible set of deployment secrets from reaching users.
- Automatic icon discovery now tries every supported high-resolution site icon location, rejects images below 96 pixels before display, and never sends local, private-network, single-label, or special-use hostnames to third-party favicon providers.
- Resolved icon choices now persist in short batched writes instead of synchronously rewriting storage after every image load, and remote image URLs have an independent 8 KB bound rather than borrowing the embedded-image allowance.
- Random identifiers retain UUID-quality entropy on older browsers that provide `crypto.getRandomValues` but not `crypto.randomUUID`, and responsive listeners retain the legacy Safari fallback.
- The top-level recovery screen no longer exposes raw exception details, while local release verification can safely use the package version when no release tag is present.
- Repository and full-history privacy gates now also reject common cloud-provider credentials, database connection strings, browser archives, logs, local databases, service-account files, and SSH key filenames.
- The public exchange-rate function now uses the Edge Runtime's built-in HTTP server instead of loading a separate remote standard-library module.
- Device-ID recovery now uses the same cryptographically strong compatibility helper as first-run setup, avoiding a startup failure on older iOS and iPadOS browsers that lack `crypto.randomUUID()`.
- Update checks now keep their ten-second timeout on browsers that do not yet implement `AbortSignal.timeout()`, using an `AbortController` fallback instead of failing before the request starts.
- The extension Content Security Policy now blocks all object embedding and fixes the document base to the packaged extension origin.
- Password recovery links now open the account panel with the new-password form visible. Sign-up and password-reset emails both use formal bilingual templates with the WhyNavo logo, request context, and safety guidance.
- Password-recovery privileges now require a verified Supabase recovery event; a URL parameter alone cannot bypass current-password verification.
- Normal password changes now reauthenticate the current email and password with a fresh Turnstile token, then verify the returned account ID before submitting the new password.
- The isolated session used to verify a normal password change is revoked after both success and failure, preventing orphaned device sessions.
- New registrations and password changes require at least 12 characters with uppercase letters, lowercase letters, and numbers. Production Supabase configuration must enforce the same policy server-side, and normal password changes also send the current password for server verification.
- Registration, login, and replacement passwords are checked against Have I Been Pwned with the privacy-preserving range API. Only a five-character SHA-1 prefix leaves the device and padded results are compared locally. Registration and replacement fail closed; an authenticated login shows a security warning for a leaked password or an unavailable check without letting a third-party outage lock existing users out.
- Cloud snapshot reads now use an account-bound RPC instead of direct table access. Both reads and writes verify the Supabase session in the database and enforce a 90-day maximum lifetime plus a 30-day inactivity timeout.
- Published 0.5.x clients retain transitional RLS-protected reads of their own snapshots. The compatibility write entry point continues to enforce ownership, session expiry, rate limits, and optimistic concurrency until the 0.6.0 archive is public and its update manifest is active.
- Local, imported, restored, and cloud payloads receive full structural validation. A failed account activation restores the exact previous local state instead of overwriting anonymous data with a blank dashboard.
- Email-verification sign-in now adopts data created before registration and shows an explicit success state; offline startup continues to use the cached account partition without treating network failure as sign-out.
- Merging anonymous data into an existing account now preserves both record sets, keeps account preferences authoritative, and retains device-local photos and custom wallpapers.
- Mutation timestamps now use a monotonic logical clock, so clock rollback or skew cannot make later edits older than timestamps the client has already observed.
- Added public-repository CI, dependency update checks, security reporting guidance, and production configuration validation.
- Added CodeQL semantic security analysis pinned to an official GitHub commit for every main-branch push, pull request, and weekly scheduled scan.
- CI, Pages deployment, and release jobs now compile-check all three Supabase Edge Functions independently so frontend success cannot hide a broken email, rate, or account-deletion function.
- The Chrome Web Store display name is now `WhyNavo - Local-first New Tab`, distinguishing the product from unrelated listings while keeping `WhyNavo` as the short name.
- Scheduled production monitoring and encrypted database backups now require the `WHYNAVO_PRODUCTION_ENABLED` launch switch, preventing false production incidents while email, backup, and legal setup are incomplete; manual preflight runs remain available.

It becomes public after the compatible cloud and staged Pages checks pass; only then does the workflow activate the update manifest and revoke the legacy entry point, so no failure stage can leave older users without either synchronization or a downloadable replacement. Release and deployment jobs also require the launch switch.
