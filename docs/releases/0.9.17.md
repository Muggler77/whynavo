# WhyNavo 0.9.17

## 中文

- 正式网页入口迁移到 `https://whynavo.com/`，不再把 Cloudflare Pages 默认子域作为用户入口。
- 登录注册回调、邮箱验证、密码重置、验证码隔离页和版本检查统一使用正式域名。
- Chrome 扩展只允许加载正式域名上的验证码页面，减少不必要的远程来源权限。
- Supabase Auth 配置脚本、线上安全检查、Edge Functions、部署工作流和商店文案同步采用正式域名，避免不同入口之间出现配置漂移。
- 邮件模板中的 Logo、验证链接和密码重置链接全部切换到正式域名。
- 本次更新不修改用户数据结构，也不删除、重排或重新归属快捷方式、文件夹、笔记、任务和小组件数据。

## English

- Moved the official web entry point to `https://whynavo.com/`; the default Cloudflare Pages subdomain is no longer presented as the user-facing origin.
- Unified sign-up redirects, email verification, password recovery, isolated CAPTCHA hosting, and update checks on the production domain.
- Restricted the Chrome extension's remote CAPTCHA permission to the production domain.
- Updated the reviewed Supabase Auth configuration, production gates, Edge Functions, deployment workflows, and store documentation to prevent origin drift.
- Updated email logos, verification links, and password-recovery links to use the production domain.
- This release does not change the user-data schema or delete, reorder, or reassign shortcuts, folders, notes, tasks, or widget data.
