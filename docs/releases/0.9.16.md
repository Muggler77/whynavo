# WhyNavo 0.9.16

## 中文

- 修复品牌图标误识别：`minimax`、`onesproxy`、`xpert` 等名称不再因为包含字母 `x` 而错误显示为 X/Twitter。
- 短英文品牌关键词现在必须作为独立词出现，避免普通站点名称触发错误品牌规则。
- 已知网站优先按真实域名识别；标题匹配仅作为导入链接、跳转链接等场景的补充。
- 图标解析缓存升级到 v6，旧版本产生的错误自动识别结果会在重新加载后失效。
- 快捷图标编辑器不再提供会直接进入页面图片元素的自由 URL 输入；在线模式只使用经过解析和尺寸检查的站点候选，仍可切换为文字图标或本地上传。
- 分阶段网页发布不再把线上返回内容写入构建目录；它只使用仓库中审查过的上一正式版本清单，避免公开发布链路接受未审查的远程数据。
- 本次更新不修改快捷方式、分组、笔记或其他用户数据。

## English

- Fixed false brand detection where names such as `minimax`, `onesproxy`, and `xpert` were incorrectly assigned the X/Twitter icon merely because they contained the letter `x`.
- Short Latin brand keywords must now appear as standalone tokens, preventing unrelated site names from triggering brand rules.
- Known sites are identified by their verified host before title-based matching is considered for imported or redirected links.
- The resolved-icon cache is upgraded to v6 so incorrect automatic matches from older builds expire after reload.
- The shortcut editor no longer exposes a free-form URL field that can flow directly into an image element. Online mode uses parsed, size-checked site candidates while text icons and local uploads remain available.
- Staged web deployment no longer writes an online response into the build directory. It uses a reviewed predecessor-version manifest tracked in the repository instead.
- This update does not change shortcuts, folders, notes, or other user data.
