# WhyNavo 0.9.33

WhyNavo 0.9.33 stabilizes the public website while scrolling and adds a data-safe update control for official Chrome Web Store installations.

## 中文

- 移除官网内容随滚动触发的透明度与位移动画，解决文字反复栅格化造成的闪烁，并增加构建回归检查，防止问题重新出现。
- 在设置的版本页明确显示更新渠道、当前状态和对应操作；中英文及 375px 窄屏布局均已检查。
- Chrome 商店正式安装版可以由用户主动检查更新；只有官方扩展 ID 且版本清单确认存在新版时才调用 Chrome 更新接口。
- 等待 Chrome 发出“更新已下载并准备安装”事件后才继续；若仍在下载，则保持当前页面并交给 Chrome 自动完成。
- 重载扩展前等待本机写入队列，并原子合并当前账号数据；任何保存失败都会阻止重载并提示重试。
- 网页版继续使用检查并刷新，本地未打包版继续使用可信 GitHub 发布包，不新增权限、远程代码或数据格式迁移。
- 0.9.33 与 0.9.32 使用相同的数据架构和同步协议，因此最低支持版本继续保持 0.9.32。

本版本不会重置快捷方式、文件夹、主页位置、小组件、笔记、任务、壁纸、账号或同步数据。Chrome 商店中的 0.9.32 审核不会被本次 GitHub/网页版发行取消或覆盖。

## English

- Removes opacity and translate-on-scroll website reveals that caused text re-rasterization and flicker, with a build regression check to keep them from returning.
- Shows the update channel, current status, and appropriate action in Settings. Both languages and the 375px layout were verified.
- Lets official Chrome Web Store installations request an update only when the exact store ID is present and the trusted version manifest says a newer release exists.
- Waits for Chrome's downloaded-and-ready event before reloading. If the package is still being prepared, the current page remains open and Chrome completes the normal automatic flow.
- Drains the local persistence queue and atomically merges the active account state before reload. Any persistence failure blocks reload and asks the user to retry.
- Keeps the hosted-app refresh path and trusted GitHub package path for unpacked builds. No permissions, remotely hosted code, or data-schema migration were added.
- Version 0.9.33 uses the same data schema and synchronization protocol as 0.9.32, so the compatibility floor remains 0.9.32.

This release does not reset shortcuts, folders, Home positions, widgets, notes, tasks, wallpapers, accounts, or synchronized data. It does not cancel or replace the Chrome Web Store's pending review of 0.9.32.
